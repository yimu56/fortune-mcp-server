# WorkBuddy 企业版 · MCP 连接器发布教程（Fortune 记账）

> 目标：把已部署在 Linux 服务器上的 `fortune-mcp-server` 注册为 WorkBuddy 企业版的自定义 MCP 连接器，
> 让全员（或指定部门）在对话里用自然语言记账、查余额。
>
> 本文按「服务端 → 后台 → 客户端」三段走。菜单名称可能随版本微调，**按括号里的关键词找**即可。

---

## 0. 全流程总览

```
① 服务端就绪            ② 企业后台注册            ③ 发布 + 授权            ④ 客户端验收
┌──────────────┐      ┌──────────────┐       ┌──────────────┐       ┌──────────────┐
│ MCP Server   │      │ 新建连接器    │       │ 私有发布/上架  │       │ 添加连接器    │
│ /mcp 可达    │ ───▶ │ 填 URL+Token │ ────▶ │ 指定可见范围   │ ────▶ │ 信任 → 绿点   │
│ /healthz ok  │      │ 拉取 13 工具  │       │ 绑定应用/市场  │       │ 对话验证记账  │
└──────────────┘      └──────────────┘       └──────────────┘       └──────────────┘
```

任何一个环节失败，先看第 5 节排查表——90% 的问题出在**网络可达性**和**鉴权头**。

---

## 1. 前置条件（三件事，缺一不可）

### 1.1 ⚠ 网络可达性（最容易踩坑）

这是本文最需要确认的一点：

> MCP Server 部署在 `<服务器地址>` 上，这是**内网地址**。
> **发起连接的是 WorkBuddy 平台侧，不是客户端本机。** 平台侧必须能路由到这台服务器，否则保存连接器时一定报“连接超时 / 无法访问”。

三种可行方案，按所在单位实际选一种：

| 方案 | 适用场景 | 要做的事 |
|---|---|---|
| **A. 私有化 / 内网版企业后台** | 后台本身部署在单位内网 | 直接把 `http://<服务器地址>:18088/mcp` 填进去，无需公网 |
| **B. SaaS 后台 + 公网入口**（最常见） | 用的是云端企业后台 | 给服务端一个**公网可访问域名 + HTTPS**：nginx 反代（见 `deploy/nginx-fortune-mcp.conf`）+ 证书 + 平台出口 IP 白名单，**不要**直接把内网地址暴露公网 |
| **C. 网关 / 专线** | 有企业网关、SASE、反向隧道 | 在网关上把 MCP 服务映射成平台可达的地址，并在网关做鉴权与审计 |

验证方法（在**平台侧**或与平台同网段的机器上执行，不要只在本机验证）：

```bash
curl -s http://<平台可达地址>/healthz
# 期望：{"status": "ok", ...}

curl -s -X POST http://<平台可达地址>/mcp -o /dev/null \
  -H "Authorization: Bearer <TOKEN>" -H 'Content-Type: application/json' \
  -w 'HTTP %{http_code}\n' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
# 期望：HTTP 200
```

### 1.2 服务端就绪

在服务器上跑完 `install.sh` 后，确认：

```bash
systemctl status fortune-mcp --no-pager     # active (running)
curl -s http://127.0.0.1:18088/healthz      # status=ok，tools=13
python3 /opt/fortune-mcp/smoke_test.py http://127.0.0.1:18088/mcp '<TOKEN>' --write
# 期望：全部通过 ✔
```

`smoke_test.py` 会真实写入两笔 0.01 的转账并转回，账户余额复原，只在账单里留下两条
“MCP 连通性测试”记录，可在 Web 端删掉。**这一步没通过就不要去后台注册**，否则后台只会给出笼统的“连接失败”。

### 1.3 权限

需要一个**企业管理员**账号（能进入企业版管理后台、能创建并发布连接器）。
普通成员只能“使用”，不能“发布”。

## 2. 注册时要用到的 4 个值

先把这几项抄在记事本里，注册过程会反复填：

| 字段 | 值 | 说明 |
|---|---|---|
| 传输方式 | **Streamable HTTP**（MCP） | 若后台还提供 SSE 选项，优先 Streamable HTTP；老版本平台只支持 SSE 时用 `/sse` |
| 服务地址 | `https://<域名>/mcp` 或 `http://<服务器地址>:18088/mcp` | **必须以 `/mcp` 结尾**，不要漏协议头 |
| SSE 地址（备选） | `http://<服务器地址>:18088/sse` | 仅当平台只支持旧版 SSE |
| 鉴权 | **Bearer Token** | 值 = `/etc/fortune-mcp.env` 里的 `MCP_AUTH_TOKEN` |
| 健康检查 | `/healthz` | 部分后台有“探活路径”输入框，填它，且此路径免鉴权 |

取 Token：

```bash
sudo grep MCP_AUTH_TOKEN /etc/fortune-mcp.env
```

## 3. 企业后台：创建并发布连接器

### 步骤 1 · 进入连接器管理

登录企业版管理后台 → 左侧找 **「连接器」/「应用与连接器」/「开放能力」** → 进入连接器列表
→ 点击 **「新建连接器」**（部分版本叫「创建 MCP 服务」「接入自定义 MCP」）。

### 步骤 2 · 填基本信息

| 字段 | 建议值 |
|---|---|
| 名称 | `Fortune 记账` |
| 唯一标识 / Code | `fortune-bookkeeping`（发布后不要改） |
| 图标 | 准备一张 256×256 PNG（可选） |
| 简介 | `连接 Fortune 记账系统，用自然语言记支出/收入/转账，查询账户余额、账本、分类与标签。` |
| 分类 | `财务` 或 `办公效率` |
| 类型 | **MCP Server**（不是 OpenAPI / 不是 Skill） |

> 简介会被模型用来判断“要不要用这个连接器”，写清**能做什么**，别写“财务系统对接平台”这种空话。

### 步骤 3 · 填连接配置

| 字段 | 值 |
|---|---|
| 传输方式 | `Streamable HTTP` |
| 服务 URL | `http://<服务器地址>:18088/mcp` |
| 鉴权方式 | `Bearer Token` / `自定义 Header` |
| Header | `Authorization: Bearer <MCP_AUTH_TOKEN>` |
| 超时 | `30s`（记账接口在内网约 1–4 s，首次登录会略慢） |

如果后台只有“自定义 Header”形式，就逐字填 `Authorization` + `Bearer <token>`（注意 Bearer 后有**一个空格**）。

后台若有 **「测试连接」/「校验」** 按钮，先点它：
- 成功标志：能列出工具、或返回 `serverInfo.name = fortune-bookkeeping`
- 失败：看第 5 节

### 步骤 4 · 拉取并勾选工具

保存连接配置后，后台一般会**自动拉取 `tools/list`**，应看到 **13 个工具**：

```
fortune_context            只读   获取分组/账本/账户与余额
fortune_list_accounts      只读   账户与余额合计
fortune_list_groups        只读   分组
fortune_list_books         只读   账本
fortune_list_categories    只读   分类树
fortune_list_payees        只读   收付款方
fortune_list_tags          只读   标签
fortune_add_expense        写入   记支出
fortune_add_income         写入   记收入
fortune_add_transfer       写入   转账
fortune_add_account        写入   新增账户
fortune_add_bill           写入   高级原始字段
fortune_login              写入   刷新令牌
```

建议：
- **首轮灰度**只勾 5 个只读工具（`fortune_context`、`fortune_list_accounts`、`fortune_list_categories`、`fortune_list_books`、`fortune_list_tags`），验证链路后再放开写入。
- 工具描述不要改。模型靠描述判断“什么时候调、怎么传参”，`fortune_add_expense` 的描述里已经写明“用户说花了多少钱时调用”，改成“新增支出”会显著降低命中率。
- 若后台有「只读 / 需确认 / 高风险」标记，把 4 个 `fortune_add_*` 标成**需确认**。

### 步骤 5 · 可见范围与授权

| 项 | 建议 |
|---|---|
| 可见范围 | 先指定 **1 个测试部门或 1–3 个测试账号**（含 `CHANGE_ME`） |
| 授权方式 | 平台统一授权（服务端用固定账号）即可；本服务默认用 `.env` 里配置的账号 |
| 数据边界 | 说明是**测试账本**，避免员工误以为在看真实财务数据 |
| 多用户隔离 | 若要求“每人用自己的记账账号”，服务端设 `FORTUNE_ALLOW_HEADER_CRED=1`，再由平台按登录用户注入 `X-Fortune-Username` / `X-Fortune-Password` 头 |

### 步骤 6 · 发布

两条路径，按用途选：

| 路径 | 适用 | 操作 | 审核 |
|---|---|---|---|
| **A. 私有发布** | 公司内部自用 | 直接点「发布」/「上线」，仅对可见范围内的成员生效 | 通常无需审核 |
| **B. 公开上架** | 对外分发 / 上市场 | 另建公开资产 → 补齐隐私说明、数据流转与资质 → 提审 | 人工 + 机器审核，约 1 周 |

> 私有版本的静态 Bearer Token **通常不允许直接上架公开市场**；要对外分发需单独走公开资产并实现 OAuth 授权。

发布后建议在后台设置项里确认三件事：
1. 连接器状态 = **已发布 / 已启用**
2. 可见范围包含测试账号
3. 调用日志/审计已开启（出事能追溯）

## 4. 客户端验收

用测试账号登录 WorkBuddy 桌面端：

1. 侧边栏 → **「专家 · 技能 · 连接器」→「连接器」** → 找到 `Fortune 记账`
2. 点 **「+」/「添加」** → 若首次使用会提示 **「需要信任」**，点 **信任**
3. 状态点变 **绿色**，卡片上显示 **13/13 工具已启用**（若只勾了 5 个则是 5/5）

然后按顺序说这 4 句话验收：

| # | 对话 | 期望 |
|---|---|---|
| 1 | “看看记账账户和余额” | 调用 `fortune_context`，返回「账户1 100.00 / 账户2 50.00」 |
| 2 | “有哪些支出分类” | 调用 `fortune_list_categories`，返回维持类/消费类/提升类/社交类 |
| 3 | “记一笔支出，午饭 25 块，用账户1，分类消费类” | 调用 `fortune_add_expense`，账户1 余额变 75.00 |
| 4 | “从账户1 转 10 块到账户2” | 调用 `fortune_add_transfer`，两账户余额相应变化 |

**验收清单**

- [ ] `/healthz` 返回 ok，`tools=13`
- [ ] 服务端 `smoke_test.py --write` 全部通过
- [ ] 后台「测试连接」成功，工具列表 13 个
- [ ] 客户端卡片绿点，工具数正确
- [ ] 4 句话验收全部命中正确工具
- [ ] 后台审计日志能看到每次 `tools/call`
- [ ] 错误场景：说“记一笔 -5 块的支出”，应被参数校验拦截并给出可读错误，而不是 500

## 5. 排查表

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 后台保存时报**连接超时 / 无法访问** | 平台侧路由不到 `<服务器地址>` | 见 1.1，换公网域名/网关；确认防火墙放行 18088；`curl` 从平台同网段验证 |
| **401 Unauthorized** | Token 缺失/不一致/多了空格 | 比对 `MCP_AUTH_TOKEN` 与后台 Header；确认 `Bearer ` 后一个空格 |
| **404** | URL 少了 `/mcp` 或多了斜杠 | 用 `http://host:18088/mcp`，不带尾斜杠 |
| **405 Method Not Allowed** | 平台用 GET 探测 `/mcp` | 正常：本服务 POST 才处理；若后台强制 GET 握手，改用 `/sse` 传输 |
| 工具列表**空的** | 平台未执行 `tools/list`，或工具全部未勾选 | 后台重新“同步/刷新工具”；确认勾选 |
| 客户端**灰点/未连接** | 没点“信任”，或令牌过期 | 重新信任；重启客户端 |
| Agent **不调用工具** | 工具描述被改、或简介太抽象 | 恢复工具描述；简介写清“记支出/查余额” |
| 调用返回 `无法连接记账服务` | 服务器 → `<服务器地址>:46031` 不通 | 服务器上 `curl http://<服务器地址>:46031/prod-api/getRsaPublicKey` |
| 调用返回 `HTTP 500 / 接口错误` | 下游业务校验失败 | 错误原文已透传，看 `content.text` 里的 `msg` |
| SSE 一直无响应 | 代理缓冲 | nginx 加 `proxy_buffering off`（模板已含） |
| 一段时间后**会话失效** | 多实例未粘滞 / TTL 到 | 单实例部署，或调大 `MCP_SESSION_TTL`，或做 `Mcp-Session-Id` 粘滞 |

服务端日志：`journalctl -u fortune-mcp -f`。

## 6. 迭代与回滚

- **改代码/配置**：`sudo systemctl restart fortune-mcp`，无需动后台连接器（URL 与 Token 不变）。
- **换 Token**：改 `/etc/fortune-mcp.env` → 重启服务 → **同一时间**更新后台连接器的 Header（两步之间会短暂 401）。
- **回滚**：保留上一版 `server.py` 等文件，覆盖后重启即可；后台配置无需变更。
- **下线**：先到后台把连接器状态改为「停用/下架」，再到服务器执行 `sudo bash uninstall.sh`（先加 `--dry-run` 预览；彻底清除用 `--yes --purge`）。

## 7. 安全合规建议（上线前逐条确认）

1. **HTTPS**：公网入口必须 TLS，证书用企业 CA 或受信 CA。
2. **IP 白名单**：只放行平台出口 IP，不做全 0.0.0.0 暴露。
3. **Token 强度**：≥ 32 位随机；`install.sh` 默认生成；不要用 `123456` 这类测试值上线。
4. **最小权限**：首轮只开只读工具；写入工具标“需确认”。
5. **数据边界**：当前连接的是占位账号的测试账本，正式接入前先确认是否要接真实账套。
6. **审计**：后台调用日志 + 服务端 journal 双留痕，保留 ≥ 6 个月。
7. **不下放下游权限**：本服务只是代理，业务系统自身的权限校验不要关闭。
